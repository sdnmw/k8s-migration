# v0.5.1 更新日志

本版本修复 n8n 等 Compose 应用使用 Traefik Docker socket 时迁移失败的问题。

## 问题修复

- 区分业务数据挂载与 Docker/容器运行时 socket。socket 不再被要求生成 PVC，也不参与 Kopia 备份；named volume、普通 bind mount 和共享卷仍按原流程迁移。
- 支持将显式配置的 Traefik Docker HTTP 标签路由转换为目标端离线 File provider，后端使用 Kubernetes Service。保留域名匹配、入口、TLS 证书解析器、受支持的响应头中间件和证书数据卷；源 Compose 文件与环境配置不变。
- 不支持的 socket 消费者、TCP/UDP 路由、隐式 Docker 路由、配置冲突和不明确的后端端口会给出具体兼容性原因，不会静默忽略。
- 新发现应用的运行时依赖进入兼容性评估；确定性运行时配置错误立即终止，不再重复尝试五次。网络等临时错误仍保留重试。
- Compose 主机默认 Docker 网桥缺失时，Kopia 辅助容器回退到 Linux 主机网络，不修改业务网络或 Docker 全局配置；安全重建启动失败后遗留的、操作标识匹配的 Created 辅助容器，避免重试卡在 `docker wait`。
- 离线包补齐仓库根目录的两份 Nextcloud Markdown 教程及其截图，可直接阅读。

## 使用与升级

使用本 Release 的 `sks-migration-center-0.5.1-linux-amd64.tar.gz` 和配套 `.sha256` 文件安装或升级。已有数据库、对象存储和管理员密码保留；v0.5.0 离线包不覆盖。

本次 Traefik 自动适配要求显式开启 Docker provider、`exposedByDefault=false`，并明确配置 HTTP router。当前支持 HTTP router、TLS certResolver、后端协议/端口及常用 Headers 中间件；其他中间件、复杂 TLS 和 TCP/UDP 配置需显式适配。迁移不会修改公网 DNS/VIP；原 Host/域名匹配规则保持不变，目标验证与人工切流时需使用相应 Host/域名。
