# 迁移生命周期

## 通用时序

1. 执行期检查：连接、权限、镜像、存储、对象存储和组件健康。
2. 在线预同步：业务仍运行时复制大部分数据。
3. 停止源业务：记录原状态并进入一致性窗口。
4. 最终备份：复制最后增量。
5. 数据传输：等待快照或文件备份在目标侧可恢复。
6. 资源转换与映射：生成目标资源并应用匹配规则。
7. 目标恢复：创建资源、恢复数据、启动工作负载。
8. 业务验证：验证必要资源、Pod/PVC、探测项和业务规则。
9. 等待人工切流：管理员确认外部入口已切换。
10. 收尾：保留源端停止状态，或执行恢复源端。

Compose 使用 Kopia 备份 named volume 和可迁移的 bind mount；Kubernetes 依据策略使用 Velero FSB 或 CSI Data Mover。没有卷的任务会跳过卷步骤。

## 重试与租约

Worker 定期写入心跳并持有任务租约。重试不会并发执行同一个 Run；租约过期且心跳停止时，页面会显示“可能卡住”并给出当前等待原因。不要在未查明原因时反复点击重新执行。
