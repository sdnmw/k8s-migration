# 第一次完整迁移

一次迁移由“发现 → 评估 → 映射 → 检查 → 执行 → 验证 → 切流 → 收尾”组成。

## 六步创建向导

1. **源环境**：选择已连接的 Kubernetes 或 Docker Compose 环境。
2. **选择应用**：选择自动发现的应用；Kubernetes 还可按 Namespace 手选资源。
3. **迁移评估**：选择目标 SKS，展开兼容性得分、BLOCKER 与 WARNING 明细。
4. **目标映射**：可选。Compose 未选择时自动创建 Namespace；Kubernetes 仅在规则匹配时改写字段。
5. **迁移检查**：选择数据迁移策略，核对镜像、存储、对象存储、停机和切流设置。
6. **确认**：复核摘要后创建 Migration Plan 和首个 Run。

## 执行阶段

平台依次执行检查、在线预同步、停止源业务、最终备份、数据传输、转换与映射、目标恢复、业务验证和人工切流。无卷应用会跳过无意义的数据步骤；具体顺序以“执行时序”页为准。

## 人工切流

“确认人工切流”表示管理员已经在平台外完成 DNS、负载均衡、Ingress、VIP 或 NodePort 入口变更。按钮本身不会自动修改外部网络。确认前应先完成目标业务登录和数据抽查。

## 迁移后的三种处理

- **保留源端停止状态**：适合正式割接，避免双写。
- **恢复源端**：按迁移前记录的 Compose 服务状态或 Kubernetes 副本数恢复源业务，目标资源保留。
- **失败后重试**：从操作菜单选择“编辑任务”修正参数，再“重新执行”；每次执行都会生成新的 Run，不覆盖历史证据。

## 成功标准

1. 任务结论为迁移成功。
2. 必要资源均存在且健康，失败/缺失为 0。
3. 卷迁移已完成，传输量和校验值合理。
4. 目标业务可以访问，迁移前准备的数据仍存在。
5. 切流或源端恢复事件与实际状态一致。
