# 安全、备份与灾难恢复

## 凭证维护

- 定期轮换管理员、Harbor、对象存储和 SSH 凭证。
- kubeconfig、私钥和 Secret 文件权限设为 0600。
- 高安全环境手动填写经可信渠道核验的 SSH 主机指纹；默认自动读取并固定保存属于首次信任，不能代替独立核验。
- 报告和截图不得包含密码、Token、Secret 值和环境变量值。

## 平台备份

至少备份 PostgreSQL、MinIO 数据、平台 Secret、Helm values、对象存储 bucket 配置和版本对应的离线包。业务迁移备份与平台数据库备份是两类数据，不能互相替代。

## 容量与清理

监控 MinIO/Kopia/Velero 容量、PostgreSQL PVC 和目标集群存储。清理备份前确认没有运行中 Run、回滚需求或审计保留要求。优先从平台任务清理入口执行，使数据库和对象存储元数据保持一致。

## 灾难恢复

恢复顺序建议为：基础存储 → PostgreSQL/Secret → API → Worker → Web → MinIO/备份索引 → 环境连接验证。恢复后先执行只读检查，再允许创建新迁移。

## 文档构建依赖的安全边界

v0.5.0 按版本约定固定 Docusaurus 3.8.1。2026-10-08 的 npm audit 对其构建依赖报告了已知漏洞；这不等于安全扫描通过。发行 Web 镜像只包含编译后的静态 HTML/JS/CSS 和 Nginx，不运行 Node、Docusaurus 开发服务器或构建工具。文档源文件及依赖锁应由可信维护者更新，不能在生产环境用开发服务器替代静态路由。后续升级构建依赖时，应重新执行构建、断链和离线浏览器测试。
